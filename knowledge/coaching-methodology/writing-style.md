# 求职写作风格指南：从"能读"到"想约面试"

> 来源：ai-job-search 项目方法论 + 求职教练经验。核心原则：雇主扫一份简历/求职信的时间是 6-10 秒，你的文字必须在这个窗口内传递"这个人能解决问题"的信号。

---

## 铁律（不可违反）

### 1. 禁止破折号

中文用逗号、句号或分号替代；英文用逗号或句号替代。破折号在 ATS 解析中经常变成乱码，且视觉上打断阅读流。

### 2. 禁止陈词滥调和无意义填充

| 删除 | 原因 |
|------|------|
| "我对 XXX 充满热情" | 每个人都这么说，等于没说 |
| "我相信我能胜任这个岗位" | 用事实证明，不要用信念 |
| "利用我的技能" | 空洞，说具体技能 |
| "快速上手" | 每个人都说自己学得快 |
| "驱动结果" | 空洞 buzzword |
| "赋能"、"闭环"、"抓手"、"沉淀"、"对齐"、"拉通" | 见 anti-ai-detection.md 黑名单 |

### 3. 每个声明都要有支撑

不是"我有很强的技术能力"，而是"我独立设计并实现了 X 系统，支撑 Y 用户，P99 延迟 Z ms"。

### 4. 禁止道歉式/过度谦虚语言

- ❌ "我想我可能可以贡献..."
- ✅ "我带来 X 能力，在 Y 项目中有 Z 成果"

- ❌ "虽然我没有太多经验..."
- ✅ "我在 X 领域的经验可以迁移到 Y"

### 5. 禁止未经验证的公司声明

求职信中关于公司的任何具体陈述（产品名、技术栈、合作伙伴、扩张计划）必须经过独立验证。**不要信任搜索摘要——验证来源页面本身。**

### 6. 面试回溯测试

写完后对每条 bullet 问自己：**面试时被追问这条，能不能不推翻重说？**

- ✅ **可以：** 重新排序经历、使用目标领域的自然同义词、强调宽泛角色中相关的侧面
- ⚠️ **注意：** 把学术+行业经验合并成一条、用 JD 术语描述只是相邻而非相同的工作
- ❌ **绝对不行：** 声称有用户没有的经验、暗示在用户没做过的领域工作过

---

## 语气

- **温暖但直接。** 友好、可接近，但自信而不傲慢。
- **对话式专业。** 不是僵硬的公司八股文，也不是随意聊天。想象一个自信的人在面试中怎么说话。
- **第一人称，主动语态。** "我搭建了"而非"该系统由候选人开发"。
- **展示，而非陈述。** 不说"我有团队精神"，写一个具体的协作例子和结果。

---

## 求职信标题

**差：** "应聘软件工程师岗位"
**好：** "AI Agent 开发工程师 — 3 年 LLM 应用落地经验"

**公式：** 核心定位 + 从 JD 中提取的关键词

---

## 可扫读结构

雇主快速扫读。按以下原则组织：

- 使用描述性小标题（不要"正文"，要"我能为这个岗位带来的"）
- 在自然的地方嵌入行业关键词
- 简洁——删除所有填充词
- **一页硬限制**

---

## 前向视角框架

求职信**不是简历的重复**。它应该向前看：

- 聚焦**你能为雇主解决什么任务**，而非你过去做了什么
- 描述你的方法：你会用什么工具、什么思路
- 解释雇主雇佣你后可以期待什么积极结果
- 用 1-2 个简短过去例子仅作为前向声明的支撑

---

## 求职信结构

### 开头段落
- 陈述岗位和写信原因（1 句）
- 立刻把你的背景连接到岗位（1-2 句）
- 针对这家公司/岗位定制，不要模板化

### 为什么是这家公司（放在前面）
- 开头之后的**第一节**应解释为什么申请这家公司
- 使用 JD 和公司官网的语言和主题
- 聚焦你能如何贡献，而非你能从中获得什么
- 如果你和公司的人聊过，自然地引用对话

### 主体段落——任务解决视角
- 以对该岗位最相关的经验开头
- 围绕**你能解决他们的哪些任务、怎么解决**来组织
- 描述你的方法：工具、思路、知识
- 适当时使用 bullet 列表（3-5 条）
- 每条 bullet 具体且结果导向
- 至少包含一个展示主动性的例子

### 结尾
- 简洁、自信、前向
- "期待与您进一步交流" 或 "欢迎随时联系讨论"
- 不乞求、不过度热情

---

## Bullet Point 风格

- 以动作动词或粗体类别标签开头
- 具体：数字、工具、结果
- 变换句式结构（不要每条 bullet 都以同样的方式开头）

---

## 不同角色类型的语言风格

### AI Agent / LLM 工程方向
- 以编程语言、LLM 框架、具体模型架构开头
- 提及数据规模、管道复杂度、token 成本/延迟
- 包含独立项目
- 示例："设计 5 阶段 Agent Pipeline，将人工排查从 40 分钟压缩至 4 分钟（10x）"

### 后端开发方向
- 以 API 设计、数据库优化、系统架构开头
- 突出性能指标（QPS、延迟、数据量级）
- 强调系统可靠性（重试、熔断、监控）

### 数据分析方向
- 以分析方法论和业务影响开头
- 突出数据规模与复杂度
- 强调驱动了什么决策、节省了多少成本

### 技术管理方向
- 以项目管理、团队领导、跨部门协作开头
- 强调技术决策和架构方向把控
- 突出团队成长和交付成果

---

## 多语言求职

- 默认使用 JD 的语言
- 用 JD 语言写的求职信要读起来自然，不像翻译
- 某些语言可能允许更温暖、更个人化的语气
- 中文简历/求职信：避免"赋能"、"闭环"等互联网黑话（见 anti-ai-detection.md）

## 提交前自检清单

- [ ] 没有破折号
- [ ] 没有陈词滥调和填充词
- [ ] 每个声明都有具体例子支撑
- [ ] 前向视角：聚焦你能解决的任务，而非过去职责
- [ ] 动机段落引用了这家公司的具体信息
- [ ] 公司名和岗位名全篇正确
- [ ] 日期是最新的
- [ ] 一页以内
- [ ] 语言匹配 JD 语言
- [ ] 称呼恰当（尽可能有具体人名）
- [ ] 标题引人注目且具体，不通用
