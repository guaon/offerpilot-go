## 求职意向（Profile Statement）模板

这是最重要的定制部分——根据方向选择句式：

### Agent 开发方向
```
X年Agent系统开发经验，擅长从零设计Agent架构、开发Tool/Function、编排多步骤工作流。主导过N个从零到一的LLM产品落地，熟悉ReAct/Plan-Execute等主流Agent模式。
```

### 后端开发方向
```
X年后端开发经验，专注高性能API设计和分布式系统。主导过日均N万QPS的服务架构，擅长性能优化和系统可靠性治理。
```

### 数据分析方向
```
X年数据分析经验，擅长从海量数据中提取业务洞察并驱动决策。覆盖N个业务线，主导过日处理N万条数据的数据管道建设。
```

### AI算法方向
```
X年AI算法经验，专注模型训练与优化。主导过N个模型的从选型到上线，在XX任务上将关键指标从A提升至B。
```

## Bullet 规则

### 硬性要求
- 每条 bullet 以动作动词开头：设计、实现、主导、优化、搭建、推动、构建、交付、解决、重构
- 禁止弱动词：负责、参与、协助、了解、使用、接触、支持
- 禁止陈词滥调：赋能、闭环、抓手、沉淀、对齐、拉通
- 每段经历 3-4 条 bullet，每条 bullet 1-2 行
- 最新角色 4-5 条，前一个角色 3-4 条，更早的角色 2-3 条

### 句式变化
**不能每条 bullet 都以同样的方式开头。** 变化示例：

```
✅ 好的变化：
- 设计并实现了5阶段Agent Pipeline，将人工排查从40分钟压缩至4分钟（10x）
- 发现P99延迟瓶颈后独立重构SQL层，将延迟从2s降至200ms
- 推动团队采用微服务架构，替代了维护2年的单体系统

❌ 单调重复：
- 设计了Agent Pipeline，提升了效率
- 设计了SQL优化方案，提升了性能
- 设计了微服务迁移方案，改善了架构
```

### Impact-First 格式
```
[成果] 通过 [方法] 实现 [具体做法]
```

示例：
```
- 将客服工单处理时间从15分钟降至3分钟，通过搭建GPT-4+RAG内部知识问答系统
- 支撑日均50万次推理调用，通过设计多Provider路由层实现负载均衡和故障转移
```

### 量化要求
- 每段经历至少 1 个量化指标
- 优先用百分比和倍数："提升 40%"、"10x 效率提升"
- 给出规模感："覆盖 100+ 工具"、"日处理 50 万条"

| 模糊表述 | 量化重写 |
|---------|---------|
| "大幅提升性能" | "P99延迟从 2s 降至 200ms (10x)" |
| "处理海量数据" | "日处理 500 万条交易记录" |
| "效果显著提升" | "F1-Score 从 72% 提升至 96%" |
| "获得好评" | "上线首周 DAU 增长 35%" |

## 页数预算

| 工作经验 | 目标页数 |
|---------|---------|
| 0-3 年 | 1 页 |
| 3-8 年 | 1-2 页 |
| 8+ 年 | 2 页 |

| 分节 | 预算 |
|------|------|
| 求职意向 | 2-3 行 |
| 技能 | 3-5 项，每项 1 行 |
| 最新角色 | 4-5 条 bullet |
| 前一个角色 | 3-4 条 bullet |
| 更早的角色 | 2-3 条 bullet |
| 教育 | 2-3 行 |
| 项目 | 2-3 个，每个 3-4 条 bullet |

**怀疑超页数时，优先删内容而非压缩排版。** 压缩排版让简历看起来拥挤。

## 相关性加权裁剪

当简历超出页数限制时，不是机械地删"最旧的"，而是按以下算法打分后删最低分：

### 每行评分 = ① + ② + ③

1. **JD 关键词命中（权重 2）**：这一行是否命中 JD 中的技术栈、能力要求、岗位职责？（命中 = 2，未命中 = 0）
2. **内容独特性（权重 1）**：这个信息是否在简历其他地方重复出现？（重复 = 0，唯一 = 1）
3. **封面信依赖度（权重 1）**：封面信是否引用了这条信息？（引用 = 1，未引用 = 0）

**删最低总分，不看它属于哪个分节。**

### 实际删除顺序（最容易 → 最后手段）

1. **冗余**：如果技能区和经历 bullet 说了同一件事，删技能区的版本（经历 bullet 是更具体的证据）
2. **求职意向水分**：纯陈述句，删掉后技能区或项目区会自然展示
3. **低相关经历 bullet**：不命中 JD 关键词的 bullet，无论它在哪个分节
4. **低相关支撑内容**：不命中 JD 的老项目、不相关的证书、可合并的语言项
5. **低相关论文/奖项**：只保留 1-2 个最匹配的
6. **最后手段**：删最早的教育经历、把老角色压缩到 2 条 bullet

### 避免的坑

- 不要机械地"删最早的角色"——如果那个角色恰好是 JD 要求的技能来源
- 不要删封面信引用的那条具体证据——面试官会对照着看
- 差一点就满页（2.02 页）时优先用微调而非删内容

## JD 关键词嵌入

- JD 中出现的核心术语，在 section 标题或前 3 条 bullet 中必须出现
- 使用 JD 的精确术语而非同义词：JD 写的 "MLOps"，简历里也写 "MLOps"，不写 "ML 部署"
- JD 中出现 3 次以上的词，简历中至少出现 1 次

## 工作年限与可见产出检查

写完简历后，用陌生人的视角审视：**日期跨度 vs 展示的工作量。** 一个 2 年的角色只写了 1 个项目，读起来像产出不足。

### 三类诚实修复（按优先级）

1. **挖掘更多真实工作**：这段时间里还有没有其他项目、内部工具、技术分享？看起来"不重要"的工作，放在简历上比留白好
2. **把阶段讲清楚**：如果时间跨度确实长，说清楚阶段——初期学习/支持团队 → 中期独立负责 → 后期交付。阶段弧线读起来像成长曲线
3. **说明为什么周期长**：数据采集周期长、需要领域专家验证、部署后持续迭代——懂行的审阅者会认可

**禁止**：编造项目、缩短在职时间。两者都是可查的，且比"看起来产出少"更致命。

## 在职中的资格

如果学位/证书在读中，**必须明确标注**，不能让读者误以为已完成：

```
✅ 教育背景
XX大学 | 计算机硕士（在读，预计 2026.06） | 2025-2026
```

纯年份区间 `2025-2026` 在 2026 年中看，读起来像已完成。确保求职意向、教育经历、可入职时间三处信息一致。

## 职业空窗期处理

- 如实说明，不回避
- 描述空窗期间如何保持专业发展
- 框架为"有意的技能积累和职业重新定位"

---

## 诚实规则

- 所有内容必须来自用户画像，禁止编造
- 重构侧重可以，改变事实和放大数字不行
- 用"面试回溯测试"检查：每条 bullet 用户能否在面试中解释清楚？如果用户要说"呃，其实我是想说..."，说明这条写过头了
- 画像中缺少的信息（如教育背景），该部分留空标注"待补充"，不要编造

---

## 多语言简历

- 如果 JD 是英文，简历用英文
- 如果 JD 是中文，简历用中文
- 分节标题和正文语言保持一致（不要正文是中文，标题是英文 "Professional Experience"）
- 中文简历同样适用所有 bullet 规则和量化要求
