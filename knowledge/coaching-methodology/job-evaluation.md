# 岗位评估框架：五维加权评分

> 来源：ai-job-search 项目方法论。核心思想：不只"能不能做"，更要评估"值不值得做"。每条 JD 都是在读一份合同草案——你要在签字前看清所有条款。

---

## 资格门（投前硬过滤）

**在评分之前，先跑两道硬过滤。** 不通过的不评分、不投递。

### 第一道：身份/签证门

读 JD 的"资格要求"/"工作权利"部分**逐字**判断：

| JD 表述 | 结论 |
|---------|------|
| 明确要求公民/永居/安全审查 | **FAIL — 硬停。** 引用原文告知用户 |
| 明确写"接受国际申请人"/"提供签证赞助" | **PASS** — 确认通过 |
| 未提及 | **PROCEED，但标记未验证。** 建议查雇主官网的 careers 页面 |

**两条容易犯错的规则：**

1. **沉默不等于许可。** 大型校招项目经常在雇主官网而非 JD 中设限。高风险行业：金融服务、政府/国防、电信、关键基础设施。
2. **公司层面的"欢迎国际申请人"不等于岗位层面的许可。** 常见模式是泛泛的欢迎声明后跟一个"具体适用项目/业务线"的有限列表。确认该岗位在列表中。

### 第二道：语言门

读 JD 中**对岗位本身**的语言要求（不是广告用什么语言写的），对照用户画像中的语言表：

| JD 要求 vs 用户语言表 | 结论 |
|----------------------|------|
| 要求用户**完全未声明**的语言 | **FAIL** — 硬停，不评分 |
| 要求用户声明了但**级别可能不够**（如 JD 要求"流利"但用户自评 B1/B2） | **FLAG，继续。** 评分正常，但明确告知用户差距 |
| 要求用户声明了的语言，级别匹配或 JD 未指定级别 | **PASS** |

**判断原则：** 读两边原文判断，不要强制套用 CEFR 量表。不确定时，偏好 FLAG 而非沉默 PASS——让用户做最终判断。

## 五维评分体系

### 1. 技术栈匹配（权重 30%）

| 分数 | 含义 |
|------|------|
| 80-100 | 核心要求是用户的主要技能 |
| 60-79 | 大部分匹配，1-2 个可学习补上的缺口 |
| 40-59 | 部分匹配，需要大量补课 |
| 0-39 | 根本性不匹配 |

**Agent 方向强匹配区：** Agent 架构设计、Tool/Function 开发、LLM 调用层、Prompt Engineering、RAG 系统
**Agent 方向中等匹配区：** 后端 API 设计、数据处理管道、向量数据库
**Agent 方向弱匹配区：** 前端开发、移动端、DevOps 专精

### 2. 经验匹配（权重 25%）

匹配的是**工作内容的实质**，不是岗位名称。一个"数据顾问"和一个"数据科学家"可能做的是同一件事。

| 分数 | 含义 |
|------|------|
| 80-100 | 同领域同角色类型的直接经验 |
| 60-79 | 相关经验，可迁移技能清晰 |
| 40-59 | 相邻经验，需要包装论证 |
| 0-39 | 无关经验 |

### 3. 行为/文化匹配（权重 15%）

| 分数 | 含义 |
|------|------|
| 80-100 | 文化与行为偏好强烈匹配 |
| 60-79 | 信号混杂但总体兼容 |
| 40-59 | 存在摩擦区域 |
| 0-39 | 显著文化不匹配 |

**红旗信号：** 部门混乱、工作以维护为主而非开发、领导层口碑差、加班文化严重。

### 4. 地点与后勤（Pass/Fail，不计入加权）

- 通勤可达：PASS
- 远程 + 偶尔到岗：PASS
- 需要搬迁：FAIL（硬性否决）
- 频繁国际出差：FLAG（与用户讨论）

### 5. 职业规划匹配（权重 30%）

评估这个岗位是否推进用户的职业目标，以及工作内容是否能**激发**而非**消耗**用户：

| 分数 | 含义 |
|------|------|
| 80-100 | 与职业方向强对齐，有明确成长路径 |
| 60-79 | 好岗位但只部分对齐长期目标 |
| 40-59 | 还不错但不太建设职业方向 |
| 0-39 | 死胡同或倒退 |

**激发型任务（Agent 方向）：** 从零搭建系统、架构设计、解决疑难杂症、技术选型
**消耗型任务（Agent 方向）：** 纯 CRUD、重复性运维、无技术含量的联调、写文档为主

## 加权计算

```
总分 = 技术栈匹配 × 30% + 经验匹配 × 25% + 行为匹配 × 15% + 职业规划 × 30%
```

（地点为 Pass/Fail，不参与加权）

## 阈值区间

| 区间 | 分数 | 建议 |
|------|------|------|
| 强匹配 | 75+ | 绝对投递，全力定制 |
| 良好匹配 | 60-74 | 投递，在求职信中解决缺口 |
| 中等匹配 | 45-59 | 慎重考虑，与用户讨论 |
| 弱匹配 | 30-44 | 除非有战略原因，否则跳过 |
| 不匹配 | <30 | 跳过 |

## 投前最佳实践：先打电话

**只有有实质性问题时才打，不要为了"被记住"而打。**

### 适合打电话的情况
- JD 有模糊或矛盾的要求
- 不清楚哪些能力是必须 vs 加分
- 岗位描述对日常工作内容语焉不详
- 有署名联系人且欢迎咨询

### 好问题范例
- "这个岗位的核心挑战是什么？"
- "日常工作在列出的职责之间怎么分配时间？"
- "对胜任这个岗位来说，哪项能力最关键？"
- "入职前 6-12 个月做到什么算成功？"

### 通话规则
- 准备 30 秒背景介绍（以防对方问）
- 通话目的是**收集信息**，不是推销自己
- 做笔记——在求职信中自然引用通话内容
